Skills de revue & qualite code

init /init

Genere ou met a jour CLAUDE.md en analysant la codebase. Donne le contexte a toutes les futures conversations.

Quand l'utiliser sur PNPI

  • Une grosse refonte a change la structure (ex: nouveaux dossiers core/, nouveaux routers)
  • Vous voulez documenter les variables d'env PNPI_*, les commandes ou conventions
  • Avant d'onboard un stagiaire ou un autre dev sur le projet

Invocation

> /init
# Claude lit tout le repo et ecrit/met a jour CLAUDE.md a la racine
Astuce PNPI — le CLAUDE.md actuel contient deja la stack, les middlewares, les commandes et les conventions (commits feat: lot N —, migrations YYYYMMDD_NN_*). Ne relancez /init que si la structure change sensiblement.

review /review

Revue de PR complete : bugs, risques, tests manquants, regressions potentielles.

Quand l'utiliser sur PNPI

  • Avant de commiter feat: lot N — ... — vous obtenez un rapport avant meme que la PR existe
  • Sur une branche feature importante avant git push
  • Apres un merge complique pour verifier qu'aucun conflit mal resolu ne traine

Invocation

> /review
# Compare la branche courante vs main, analyse le diff, sort un rapport structure
Astuce PNPI — utile apres les gros lots qui touchent plusieurs routers (ex : lot 61 qui a modifie auth, SLA, webhooks, health en meme temps). La revue attrape les regressions croisees.

Checklist typique qu'il applique ici

  • Datetime as_utc() partout ou on compare avec now_utc() (piege SQLite recurrent)
  • Endpoints FastAPI avec Depends(require_roles(...)) coherents
  • Pattern Array.isArray(data) cote frontend au lieu de data.xxx || data || []
  • Migrations Alembic upgrade() + downgrade() reversibles

security-review /security-review

Scan de securite OWASP sur les changements en cours : auth, injection, XSS, SSRF, path traversal, secrets.

Quand l'utiliser sur PNPI IMPORTANT

  • Tout changement dans backend/app/core/auth.py, core/sanitize.py, core/webhooks.py
  • Ajout d'un router qui accepte payload: dict sans schema Pydantic (ex : announcements.py, admin.py)
  • Modification du CSRF, CORS ou du rate limiter
  • Upload de fichiers (documents.py, upload_validation.py)
  • Avant chaque deploiement prod

Invocation

> /security-review
# Analyse uniquement les fichiers modifies vs main, focalise sur OWASP top 10
Cas deja attrapes sur PNPI — SSRF dans les webhooks (lot 61), sanitization XSS des annonces, pagination sans borne, JWT TTL incoherent cookie/backend. Relancez ce skill a chaque changement sensible.

simplify /simplify

Trouve les duplications, abstractions prematurees, code mort et propose des refactors concrets.

Quand l'utiliser sur PNPI

  • Apres avoir ajoute 3 ou 4 endpoints similaires (liste + detail + stats) — factorisation possible
  • Composants React qui repetent le pattern fetch + Array.isArray + setState (9+ pages sur PNPI)
  • Fonctions utilitaires dupliquees entre core/ modules

Invocation

> /simplify
# Focus sur le diff courant ; pas une revue de tout le repo
Candidats evidents sur PNPI — les 10+ pages avec le meme boilerplate fetchBackendProfile + redirect + Promise.all + try/catch meriteraient un HOC ou un middleware Next.js.

Skills UI & design

web-interface-guidelines /web-interface-guidelines

Revue UI basee sur les guidelines Vercel : accessibilite, responsive, performance perceived, micro-interactions.

Quand l'utiliser sur PNPI

  • Apres avoir cree une nouvelle page /pnpi/*
  • Avant de montrer une demo au ministre ou au directeur
  • Quand une page doit supporter operateur ET ministre (responsive + keyboard nav)

Invocation

> /web-interface-guidelines

Criteres qu'il verifie (priorites PNPI)

  • Contraste AA/AAA (cruciale pour un site gouvernemental)
  • aria-label, aria-expanded, role coherents (annuaire, kanban, mega-nav)
  • :focus-visible defini — PNPI utilise deja .skip-link & data-theme
  • Pas de alert()/confirm() natifs — PNPI a ConfirmDialog + Toast
  • Skeleton loaders au lieu de spinners vides (PNPI a SkeletonLoader)
Identite visuelle PNPI — il connait la palette Gabon : #006233 (vert), #0c7eb4 (bleu), #f2b800 (jaune), #051b36 (ink). Rappelez-lui de verifier la coherence si vous ajoutez des composants.

Skills Claude API & documentation

claude-api

Build, debug et optimisation d'apps utilisant Claude API / Anthropic SDK. Ajoute automatiquement le prompt caching.

Pertinence sur PNPI — tres forte

Le todo pending « IA question-reponse (integration Claude API) » rentre exactement dans ce skill. Aujourd'hui ChatAssistant.tsx utilise une FAQ statique. Claude peut la remplacer par un vrai appel a claude-sonnet-4-6 avec :

  • Prompt caching sur la FAQ PNPI (35+ Q/R) — economise ~80% des tokens
  • Contexte utilisateur (role, ATI en cours) injecte via system prompt
  • Streaming dans le widget ChatAssistant existant

Declenchement automatique

# Des que vous ecrivez ceci dans un fichier...
> import Anthropic from "@anthropic-ai/sdk"
# ...Claude charge le skill claude-api et applique les bonnes pratiques.
Piege PNPI — si vous ajoutez ce skill, stockez la cle dans PNPI_ANTHROPIC_API_KEY (suivre la convention PNPI_*) et ajoutez-la dans .env.example. Ne JAMAIS commiter la cle reelle.

context7-mcp

Recupere la documentation a jour de toute lib/framework. Contourne les hallucinations du modele sur les API recentes.

Pertinence sur PNPI — tres forte

PNPI utilise enormement de libs qui evoluent vite. Le skill se declenche des qu'on mentionne une lib :

  • Next.js 14+ — Server Actions, cookies() async, params: Promise en route handlers
  • SQLAlchemy 2.x — nouveau style select(), Mapped[], migrations typed
  • FastAPI — lifespan, Annotated, nouveaux decorateurs
  • Alembic — autogenerate avec types customs
  • SWR, Recharts, Leaflet, react-pdf — breaking changes frequents
  • Ruff — regles qui changent de version en version

Comment l'invoquer

> Comment faire du prompt caching avec l'Anthropic Python SDK en 2026 ?
# Claude appelle automatiquement context7 → docs officielles a jour.

> Comment gerer Server Actions avec revalidateTag en Next.js 14 ?
Regle d'or PNPI — pour toute lib, demandez « verifie avec context7 » si la reponse semble suspecte. Evite les reponses obsoletes sur Alembic/SQLAlchemy qui coutent des heures de debug.

Skills config & productivite

update-config

Modifie ~/.claude/settings.json ou .claude/settings.local.json du projet. Permissions, hooks, env vars.

Cas d'usage PNPI

Automatisations utiles

> Apres chaque edit de fichier *.py, lance ruff check
> Avant chaque commit, lance pytest
> A la fin de chaque session, affiche git status

Permissions pre-approuvees

> allow all git commands
> allow npm run dev
> allow uvicorn
> allow ruff check/format

Env vars utiles

> set PNPI_LOG_LEVEL=DEBUG pour ce projet uniquement
> set PNPI_FF_GRAPHQL_API=1 pour activer GraphQL en dev
Portee — il faut preciser global (~/.claude) ou projet (.claude dans PNPI). Par defaut, permissions sensibles = projet ; hooks de lint = projet ; raccourcis = global.

Idees pour PNPI

fewer-permission-prompts /fewer-permission-prompts

Scanne les transcripts recents, identifie les outils en lecture seule qui declenchent des prompts, et propose une allowlist.

Pertinence sur PNPI

Vous faites beaucoup de git status, git diff, curl localhost:8000/*, netstat, python -m pytest, npm run build. Ce skill les detecte et les pre-approuve dans .claude/settings.json.

> /fewer-permission-prompts
# Retourne une allowlist prioritee ; vous choisissez quoi appliquer.
A relancer periodiquement (tous les 20 sessions) — les habitudes changent, l'allowlist aussi.

Skills automatisation & cron

loop /loop [interval] [commande]

Execute une commande (ou slash-command) a intervalle regulier dans la session courante. Sans intervalle, Claude s'auto-rythme.

Cas PNPI

  • Surveiller le build prod : /loop 2m npm run build
  • Surveiller les tests pendant le dev : /loop 3m pytest tests -q
  • Verifier l'etat du deploy : /loop 5m curl -s http://localhost:8000/health
  • Self-paced — /loop /check-deploy — Claude decide du rythme selon le contexte

Invocation

> /loop 5m npm run build
> /loop /review                # revue automatique apres chaque commit
> /loop                         # mode autonome, self-paced
Attention — arreter explicitement avec Ctrl+C ou une instruction claire (« stop the loop »). Un loop oublie peut consommer beaucoup d'API tokens.

schedule

Cree, liste, met a jour des agents distants planifies (cron-style ou one-shot). Tourne sans que votre session soit ouverte.

Cas PNPI de grande valeur

TacheFrequenceBenefice metier
Lancer scripts/backup_s3.py Tous les jours a 2h Sauvegarde BD automatique
Lancer scripts/cron_tasks.py (expirations, SLA) Toutes les heures Alertes SLA en temps reel, badges a jour
Lancer /security-review Chaque lundi matin Audit securite hebdo avant la revue de direction
Envoyer le digest quotidien via core/digest.py Tous les jours a 7h Email resume pour ministre/directeur
Generer le bilan mensuel core/executive_report.py 1er de chaque mois Rapport automatique pour audience ministerielle

Invocation

> /schedule
# Assistant vous guide : cron expression, fuseau (Africa/Libreville), commande

> Schedule /security-review every Monday at 8am Africa/Libreville
> Run /check-sla-overdue once tomorrow at 9am
Fuseau Gabon — toujours preciser Africa/Libreville (UTC+1, pas d'heure d'ete). Les audiences ministerielles sont en heure locale, pas UTC.

Workflow type — une session PNPI ideale

  1. Debut de session — git status + lire CLAUDE.md (auto-charge). Si le repo a bouge, /init.
  2. Feature — code normalement. Mentionnez la lib (« comment utiliser Recharts... ») → context7-mcp se declenche.
  3. Si boucle repetitive (curl health pendant un deploy, pytest apres chaque edit) → /loop.
  4. Avant commit — /simplify puis /review. Si changement sensible → /security-review.
  5. Avant push — /web-interface-guidelines si page UI touchee.
  6. Fin de session — commit feat: lot N — + push.
  7. Taches recurrentes (backup, digest, audit) — /schedule une fois pour toutes.
